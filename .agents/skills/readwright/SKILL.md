# readwright

## Overview

readwright renders `README.md` from a Jinja2 template (`README.md.j2`) plus a config
file (`readme.yaml` or `[tool.readme]` in `pyproject.toml`). `README.md` carries a
`<!-- generated by readwright -->` marker and is **never hand-edited** — edit the
template/config, then re-render.

## Workflow

1. New project: `readwright init` (autodetects owner/repo/name/license from git
   remote + manifest files). Existing README to preserve: `readwright init
   --from-readme`. Prefer config in `pyproject.toml`: `readwright init --pyproject`.
2. Edit `README.md.j2` — it extends the packaged `base.md.j2` and overrides only the
   `{% block %}` sections it needs — and/or `readme.yaml`.
3. `readwright render` to write `README.md` (`--watch` to re-render on save, `-o -`
   to preview on stdout instead of writing).
4. `readwright check` before committing — exits 1 with a diff if `README.md` is
   stale versus what the template+config would produce. This is what CI / the
   `readwright-check` pre-commit hook run; if it fails, run `render` again, don't
   hand-patch `README.md`.

## Commands

| Command | Purpose |
| --- | --- |
| `readwright init [--from-readme] [--pyproject]` | Scaffold `readme.yaml` + `README.md.j2` |
| `readwright render [--watch] [-o -] [--user-config]` | Write `README.md` |
| `readwright check` | Fail with a diff if `README.md` is stale (CI/pre-commit) |
| `readwright badges` | List available badge presets |
| `readwright blocks` | List overridable template blocks/partials |
| `readwright show <template>` | Print a packaged template (`base.md.j2` for the block order, or e.g. `partials/install.md.j2`) to copy and customize |

All accept `-C/--root` (repo root) and `-c/--config` (explicit config path) as
options *after* the subcommand, e.g. `readwright render -C /path/to/repo` —
`readwright -C /path render` fails with "No such option: -C".

## Template helpers

Full reference with examples: [helpers.md](helpers.md). Quick index:

| Helper | Purpose |
| --- | --- |
| `badge()`, `shield()`, `badges()`, `donate_badges()` | Badges from presets, custom shields.io badges, or config-driven rows |
| `screenshot()`, `screenshots()`, `image()`, `logo()`, `video()`, `unsplash()` | Images: single shot, gallery, explicit image, theme-aware logo, video/gif, Unsplash hero |
| `toc()` | Table of contents from headings below the call |
| `changelog()` | Latest N entries from `CHANGELOG.md` |
| `cli_help()` | Runs a command and fences its `--help` output (needs `allow_exec: true`) |
| `include_file()`, `code_block()`, `snippet()` | Pull in a file, a fenced file, or a marked region |
| `config_table()`, `env_table()`, `entry_points_table()` | Tables from YAML/TOML/JSON, `.env` files, `[project.scripts]` |
| `gh_link()`, `spdx_link()`, `my_ha_link()` | Repo-relative GitHub links, SPDX license link, My Home Assistant buttons |
| `callout()`, `details()`, `center()`, `columns()` | GitHub alerts, collapsibles, centered blocks, side-by-side layout |
| `contributors()` | Avatar grid |
| `flow_install_cmd()`, `mc_versions()`, `mod_dependencies()`, `related_repos()` | Flow Launcher / Minecraft mod / related-repo tables |
| `git_sha()`, `git_tag()`, `today()` | Build metadata — these change between renders, so `check` will flag a README rendered with them as stale until re-rendered at release/CI time |
| `project.*`, `vars.*` | Autodetected repo metadata and free-form config values |

Image helpers emit plain markdown by default; pass `width=`, `html=True`, or set
`screenshots.style: html` to get `<img>`/`<picture>`/`<table>` output instead.

## Overriding blocks and partials

`base.md.j2` blocks: `header`, `badges`, `donate`, `toc`, `screenshots`, `install`,
`usage`, `extra`, `contributing`, `license`. Override any block in `README.md.j2`:

```jinja
{% extends "base.md.j2" %}
{% block usage %}
## Usage
{{ screenshot("main", width=600) }}
Run `{{ project.name }} --help`.
{% endblock %}
```

Add to the top badge row without touching the config list via the `badges_extra` /
`donate_extra` hooks. Any packaged partial can be shadowed by a same-named file
under `templates/partials/` in the repo (or `~/.config/readwright/templates/` for
all repos) — `readwright show <partial>` prints the original to copy.

To insert a whole new section where there's no dedicated hook (e.g. a Changelog
section between Contributing and License — there's no `contributing_extra` block),
override the nearest existing block and call `{{ super() }}` to keep its content,
then append (or prepend) yours:

```jinja
{% block contributing %}
{{ super() }}

## Changelog

{{ changelog(2) }}
{% endblock %}
```

## Configuration (`readme.yaml`)

```yaml
template: README.md.j2
templates: [../shared-readme-templates, "pkg:my_org_templates"]  # extra search paths
output: README.md
strict: false                # missing screenshot -> error, not warning
allow_exec: false             # let cli_help() run commands during render
badges_style: flat-square     # shields.io style for every badge
related: [{repo: other-tool, description: Sibling project}]
banner: {unsplash: photo-1518770660439-4636190af475, credit: Name, user: handle}
screenshots: {dir: docs/screenshots, width: 720, style: markdown}
badges: [pypi, python, license, {preset: ci, workflow: test.yml}, {shield: {label: Docs, message: latest, color: success}}]
badges_custom:
  discord: {label: Discord, message: chat, color: 5865F2, link: https://discord.gg/xyz}
donate: [kofi, github-sponsors]
donate_handles: {kofi: yourname, github-sponsors: yourname}
project: {name: ..., owner: ..., repo: ..., tagline: ..., pypi: ..., npm: ..., license: ..., ci_workflow: ...}
vars: {anything: you like}
```

Metadata not set explicitly is autodetected from the git remote, `LICENSE`, and
whichever manifest exists (`pyproject.toml`, `package.json`, `Cargo.toml`, `go.mod`,
`*.csproj`, Gradle `gradle.properties`, `hacs.json`, Flow Launcher `plugin.json`) —
the install section adapts to the detected project type. Shared values (donation
handles, owner, custom badges) go in `~/.config/readwright/config.yaml`; `init`
bakes them into the new `readme.yaml`, or merge them ad hoc with `render
--user-config`.

## Screenshots

Drop images in `docs/screenshots/` (or the configured `screenshots.dir`).
`screenshot("main")` finds `main.{png,jpg,gif,webp,svg}`; a `main-dark.*` +
`main-light.*` pair becomes a theme-aware image using GitHub's
`#gh-light-mode-only` / `#gh-dark-mode-only` fragments. `screenshots(columns=2)`
builds a gallery of everything in the directory; control order/captions with
`order=[...]`, `captions={...}`, or a `captions.yaml` file in the folder.

## pre-commit and CI

```yaml
# .pre-commit-config.yaml
- repo: https://github.com/Garulf/readwright
  rev: v0.4.0   # pin to the latest release tag
  hooks:
    - id: readwright-check
```

```yaml
# .github/workflows/ci.yml
- uses: Garulf/readwright@v0.4.0
  with:
    mode: check   # or render
```

## Common mistakes

| Mistake | Fix |
| --- | --- |
| Editing `README.md` directly | Edit `README.md.j2`/`readme.yaml`, then `readwright render` |
| `readwright check` fails in CI only | A helper like `git_sha()`/`git_tag()`/`today()` makes output change between renders — avoid them in checked README content, or re-render right before the check |
| `cli_help()` renders empty/errors | Set `allow_exec: true` in config — it's off by default |
| Screenshot not picked up | Check the file lives in `screenshots.dir` (default `docs/screenshots/`) and matches the base name passed to `screenshot()` |
| Custom badge/partial ignored | Custom badges go under `badges_custom` in config, not a template edit; custom partials go in `templates/partials/<same-name>` to shadow the packaged one |
