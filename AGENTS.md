# AGENTS.md

readwright is a Python CLI that renders GitHub `README.md` files from Jinja2 templates
(`README.md.j2` + `readme.yaml`), with badge, screenshot, TOC, and changelog helpers.
Package lives under `src/readwright/`; console entry point is `readwright.cli:app`
(Typer). Python >=3.11, dependency/build managed with `uv` + `hatchling`.

## Setup

```sh
uv sync --group dev
```

## Running things

Always run tools through `uv run` (or `uv run tox -e <env>`) so the project's own venv
and locked dependencies are used, not whatever's on PATH.

```sh
uv run pytest                    # run the test suite
uv run pytest tests/test_cli.py  # single file
uv run ruff check src tests      # lint
uv run ruff format src tests     # format
uv run tox                       # full matrix: py311, py312, py313, lint
uv run tox -e lint               # lint env only (ruff check + ruff format --check)
uv run readwright render         # regenerate README.md from README.md.j2 + readme.yaml
uv run readwright check          # fail with a diff if README.md is stale vs. the template
```

`tests/golden/` holds golden-file fixtures for renderer output — if you touch
`renderer.py`, `helpers.py`, or any template partial, check whether golden files need
regenerating rather than hand-editing expected output.

## Before committing

- `pre-commit` is configured (`.pre-commit-config.yaml`): gitleaks, standard hygiene
  hooks, and `ruff`/`ruff-format` run on every commit; `pytest` and
  `readwright check` run on `pre-push`. Run `uv run pre-commit run --all-files` if you
  want to check before pushing without waiting for the hook.
- **`README.md` is generated — never edit it directly.** Edit `README.md.j2` (the
  Jinja2 template) and/or `readme.yaml` (the config), then run
  `uv run readwright render` to regenerate `README.md`. The file itself carries a
  `<!-- generated by readwright -->` marker; editing it by hand will be silently
  overwritten and will fail the `readwright check` pre-push hook / CI.
- Keep `ruff` clean: `select = ["E", "F", "I", "UP", "B", "SIM"]`, line length 100
  (see `pyproject.toml`).
- This project versions with hand-bumped `pyproject.toml` (no release-please). Bump
  `version` yourself for a release-worthy change — patch for fixes, minor for new
  features/helpers — and follow Conventional Commits (`feat:`, `fix:`, `chore:`, ...).

## Layout

- `src/readwright/cli.py` — Typer commands: `init`, `render`, `check`, `badges`,
  `blocks`, `show`, `skill`.
- `src/readwright/renderer.py` — Jinja2 environment setup and rendering pipeline.
- `src/readwright/helpers.py`, `badges.py`, `images.py`, `toc.py`, `changelog.py`,
  `metadata.py` — the template helper functions exposed to `README.md.j2`
  (`badge()`, `screenshot()`, `toc()`, `changelog()`, `project.*`, etc.) and repo
  metadata autodetection (git remote, `LICENSE`, manifest files like
  `pyproject.toml`/`package.json`/`Cargo.toml`/`go.mod`/`*.csproj`).
- `src/readwright/config.py` — `readme.yaml` / `[tool.readme]` config model
  (pydantic).
- `src/readwright/templates/` — packaged `base.md.j2` and partials that a project's
  own `README.md.j2` extends/overrides.
- `examples/` — worked example projects (`kitchen-sink`, `rust-cli`, `go-cli`,
  `dotnet-tool`, `node-cli`, `config-only`) exercising every helper; useful as
  reference when adding or changing a helper's behavior.
- `action.yml` — GitHub Action wrapper for `readwright check`/`render` in CI.
- `.agents/skills/readwright/` — the agent skill (`SKILL.md` + `helpers.md`) that
  documents the render/check workflow, config keys and template helpers for coding
  agents. `.claude/skills/readwright` is a symlink to it, and hatch `force-include`s
  it into the wheel as `readwright/.agents/skills/readwright/`; `readwright skill
  --install` copies it out again (in the dev checkout the command falls back to the
  repo-root directory). When a helper, config
  key, CLI flag or block is added or changed, update the skill in the same change.

## Testing conventions

- `tests/` mirrors `src/readwright/` module-for-module (`test_badges.py`,
  `test_renderer.py`, etc.) plus `test_examples.py`, which renders the projects
  under `examples/` and is a good smoke check when changing template helpers or the
  renderer.
- New template helpers should get both a unit test and, where relevant, coverage
  in `examples/kitchen-sink` since the README documents the full helper set from
  that project's usage.
